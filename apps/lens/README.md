# Catch lens (Even Hub plugin)

Started from Even's `asr` template (`npx degit even-realities/evenhub-templates/asr`), SDK bumped to 0.0.16. The template's speech-to-text stub and `VITE_STT_API_KEY` are gone: the lens streams the glasses mic to the Catch server (`wss://catch-g2.fly.dev/audio`, the one origin in `app.json`) and draws what the server sends. Since P1a: no dot until the server says Catch can hear (D37), then the dim dot top right; a name line in the lower third for as long as the server holds it. Since P1b: the names page on a tap (a dim header `this conversation 1/2`, the names, the hint `↓ promises`; or `this conversation · nothing held`), for as long as the server holds it; a long-press goes to the server, which ends the conversation. Each launch carries a random lens id, so the server tells a reconnect from Catch starting again. While the server is unreachable there is no dot, and the lens keeps trying it every two seconds.

Commands run from `catch/`:

- `npm run local` (from `catch/`, see its README), then `npm run lens:simulate`: the whole of Catch on this machine, the lens pointed at the local server with the matching token. Or by hand: `npm run lens:dev`, then `npm run lens:simulate`; `VITE_CATCH_SERVER=ws://localhost:8080 npm run lens:dev` points a local build at a local server (never in `app.json`). The server's `/audio` takes only the shared token: put `VITE_CATCH_TOKEN=<the CATCH_AUDIO_TOKEN value>` in an untracked `apps/lens/.env.local` before `lens:dev` or `lens:pack`; it is never committed.
- `npm run lens:build`: `apps/lens/dist/`.
- `npm run lens:pack`: `catch.ehpk` for Even Beta, always pointed at `wss://catch-g2.fly.dev` with `VITE_CATCH_TOKEN` built in (`scripts/pack-lens.mjs`; see `catch/README.md`, "Even Beta").

Since P2b′ (D130), the page itself is Catch on the phone: the Even app shows the plugin's page on the phone while the glasses run it, and the page draws the history of conversations (D100) and, on a tap, one conversation's screen with YOU and OWED TO YOU (D98; tick boxes drawn but inert, tick-off is cut), read from the server's phone API (`/phone/…` on the http(s) twin of the server origin) with the same shared token. A conversation shows up there only once it ends with a promise or a keep, which P2a, P4 and P5 make. Under `npm run local` the page reads the local server.

Since P5 the promises page lists the promises owed to the wearer after the wearer's own (`owed: Dev sends the agenda`), and a tap with no names held but promises held shows the names page (header and hint) rather than `nothing held`. The page starts the lens only where an Even host has put its bridge on it (`window.flutter_inappwebview`, injected by the Even app and by the simulator): opened in a plain browser tab it is the phone page alone and never opens `/audio`, so it cannot take the wearer's session from the simulator or the glasses (`src/boot.ts`).

Files: `src/main.ts` (the Even app's bridge, the phone page, the phone-side status line, through `src/boot.ts`, which starts the lens only where there is a bridge), `src/phone.ts` (the phone page's two screens), `src/lens.ts` (the views it draws, the socket and its reconnects, taps to the server, exit; takes its bridge, so the test harness runs it on the real SDK against a stand-in Even app), `src/frames.ts` (an SDK audio event to a wire frame, with `speakerRole` and `direction`), `../../shared/wire.ts` (the frame format), `../../shared/lens-protocol.ts` (the views and the taps), `glyphs.html` with `src/glyphs.ts` (the glyph check, not part of the plugin build).
